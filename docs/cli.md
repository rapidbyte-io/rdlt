# The `rdlt` command line

Generated by `cargo run -q -p rdlt-cli --example reference`.

## `rdlt`

```text
Write, check, run, inspect and certify rdlt pipelines and connectors

Usage: rdlt [OPTIONS] <COMMAND>

Commands:
  init         Writes a starter document
  check        Builds the pipeline a document describes: validates it, places and handshakes its connectors, checks its streams, modes and transforms; no data moves
  discover     Prints the source's catalog
  run          Runs the pipeline a document describes; the first SIGINT or SIGTERM stops it after its next commit, a second at once
  state        Resets what a pipeline committed; it opens a session, which fences a run of the pipeline in progress, as any write does
  schema       Prints the document's JSON Schema, or a connector's configuration schema
  connectors   Lists what the host can place
  certify      Certifies a connector, from its binary or at its endpoint, against the protocol's clauses
  connector    Makes connector projects
  completions  Prints shell completions
  help         Print this message or the help of the given subcommand(s)

Options:
      --host <PATH>
          The operator's host file; by default `$XDG_CONFIG_HOME/rdlt/host.yaml`, where it exists

      --connectors <DIR>
          A directory local connectors are found in; by default `$XDG_DATA_HOME/rdlt/connectors`

      --trust-binaries
          Runs local connectors with your own access, in no sandbox

      --writable <PATH>
          A root a document may let its connectors write beneath

      --readable <PATH>
          A root a document may let its connectors read beneath

      --allow-network
          Lets a document let its sandboxed connectors share this host's network, its loopback services included

      --allow-env <NAME>
          An environment variable a configuration's `${env:NAME}` may reach

      --allow-files <DIR>
          A private directory a configuration's `${file:/path}` may reach beneath

      --tls-cert <PATH>
          The host's certificate chain, in PEM, for remote connectors

      --tls-key <PATH>
          The host's private key, in PEM

      --tls-ca <PATH>
          The CA bundle remote connectors' certificates chain to, in PEM

      --output <OUTPUT>
          How results print: plain on a terminal and JSON elsewhere, or as named
          
          [default: auto]
          [possible values: auto, plain, json]

      --log-level <LEVEL>
          The least level logged to standard error; `RUST_LOG`, where set, wins
          
          [default: warn]

  -h, --help
          Print help

  -V, --version
          Print version

```

## Exit codes

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | certify findings: a clause failed, or one that applies was not observed |
| 2 | config: the document, the host's policy, a placement or a secret reference |
| 3 | schema: data does not fit its table's schema under its policy |
| 4 | source: the source failed |
| 5 | destination: the destination failed |
| 6 | transform: a transform failed |
| 7 | fenced: a newer run or session of the pipeline opened |
| 8 | memory: the budget had no room for what the run holds |
| 64 | usage: the command line is wrong |
| 70 | internal: a defect in rdlt |
| 74 | I/O: a file, binary or stream could not be read or written |
| 130 | SIGINT: interrupted; the report says whether the stop was clean |
| 143 | SIGTERM: terminated; the report says whether the stop was clean |
