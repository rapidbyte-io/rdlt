# The `rdlt` command line

Generated by `cargo run -q -p rdlt-cli --example reference`.

## `rdlt`

```text
Write, check, run, inspect and certify rdlt pipelines and connectors

Usage: rdlt [OPTIONS] <COMMAND>

Commands:
  init         Writes a starter document
  check        Builds the pipeline a document describes: validates it, places and handshakes its connectors, checks its streams, modes and transforms; no data moves
  discover     Prints the source's catalog
  run          Runs the pipeline a document describes; the first SIGINT or SIGTERM stops it after its next commit, a second at once
  state        Resets what a pipeline committed; it opens a session, which fences a run of the pipeline in progress, as any write does
  schema       Prints the document's JSON Schema, or a connector's configuration schema
  connectors   Lists what the host can place
  certify      Certifies a connector, from its binary or at its endpoint, against the protocol's clauses
  connector    Makes connector projects
  completions  Prints shell completions
  help         Print this message or the help of the given subcommand(s)

Options:
      --host <PATH>
          The operator's host file; by default `$XDG_CONFIG_HOME/rdlt/host.yaml`, where it exists

      --connectors <DIR>
          A directory local connectors are found in; by default `$XDG_DATA_HOME/rdlt/connectors`

      --trust-binaries
          Runs local connectors with your own access, in no sandbox

      --writable <PATH>
          A root a document may let its connectors write beneath

      --readable <PATH>
          A root a document may let its connectors read beneath

      --allow-network
          Lets a document let its sandboxed connectors share this host's network, its loopback services included

      --allow-env <NAME>
          An environment variable a configuration's `${env:NAME}` may reach

      --allow-files <DIR>
          A private directory a configuration's `${file:/path}` may reach beneath

      --tls-cert <PATH>
          The host's certificate chain, in PEM, for remote connectors

      --tls-key <PATH>
          The host's private key, in PEM

      --tls-ca <PATH>
          The CA bundle remote connectors' certificates chain to, in PEM

      --output <OUTPUT>
          How results print: plain on a terminal and JSON elsewhere, or as named
          
          [default: auto]
          [possible values: auto, plain, json]

      --log-level <LEVEL>
          The least level logged to standard error; `RUST_LOG`, where set, wins
          
          [default: warn]
          [possible values: off, error, warn, info, debug, trace]

      --color <WHEN>
          When output is coloured: where it is written to a terminal, always, or never
          
          [default: auto]
          [possible values: auto, always, never]

  -q, --quiet
          Prints only results and failures: no progress, notes or event lines

  -h, --help
          Print help

  -V, --version
          Print version

Examples:
  rdlt init                  Writes a starter document, rdlt.yaml
  rdlt check rdlt.yaml       Builds the pipeline it describes, moving no data
  rdlt run rdlt.yaml         Loads it
  rdlt certify ./connector   Certifies a connector against the protocol's clauses

```

## `rdlt certify`

```text
Certifies a connector, from its binary or at its endpoint, against the protocol's clauses

Usage: certify [OPTIONS] [TARGET]

Arguments:
  [TARGET]
          The connector: its binary's path, or the `grpcs://host:port` endpoint it listens at

Options:
      --role <ROLE>
          Certify this role alone; by default, every role the connector serves
          
          [possible values: source, destination]

      --config-file <PATH>
          A file holding the connector's configuration, as JSON, or `-` to read it from standard input; an empty object without it; a text value may refer to a secret as `${env:NAME}` or `${file:/absolute/path}`, where `--allow-env` and `--allow-files` allow it, and no report then shows the secret

      --network
          Lets the sandboxed connector reach the network

      --env <NAME>
          An environment variable a spawned connector keeps; it otherwise starts with glibc's malloc tunables alone, and in a sandbox `TMPDIR` names its scratch directory, whatever it was

      --kill-seed <SEED>
          Kills the connector at the points this seed draws, as a failed kill clause reports, to reproduce the failure

      --kill-timeout <SECONDS>
          Gives each kill clause this many seconds for all its loads, rather than 300: a connector slower than about two seconds a commit needs more

      --credit-watch <MS>
          Watches a read whose credit is spent this many milliseconds after each grant, from 1 to 1000, rather than 1000: `P-CREDIT` then takes four times as long, and its pass notes the watch

      --timeout <SECONDS>
          Ends the certification after this many seconds, rather than 3600, failing every clause of a role still certifying then

      --no-timeout
          Lets the certification take as long as its clauses' own bounds allow

      --require <REQUIRE>
          What exits 0: `complete`, every clause that applies seen to be met; `partial`, none failed and one passed, whatever was not observed
          
          [default: complete]
          [possible values: complete, partial]

      --clauses
          Prints every clause, in Markdown, and exits

      --host <PATH>
          The operator's host file; by default `$XDG_CONFIG_HOME/rdlt/host.yaml`, where it exists

      --connectors <DIR>
          A directory local connectors are found in; by default `$XDG_DATA_HOME/rdlt/connectors`

      --trust-binaries
          Runs local connectors with your own access, in no sandbox

      --writable <PATH>
```

## Exit codes

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | certify findings: a clause failed, or one that applies was not observed |
| 2 | config: the document, the host's policy, a placement, a connector the host has none of, or a secret reference |
| 3 | schema: data does not fit its table's schema under its policy |
| 4 | source: the source failed |
| 5 | destination: the destination failed |
| 6 | transform: a transform failed |
| 7 | fenced: a newer run or session of the pipeline opened |
| 8 | memory: the budget had no room for what the run holds |
| 64 | usage: the command line is wrong |
| 70 | internal: a defect in rdlt |
| 74 | I/O: a file, a binary named on the command line, or a stream could not be read or written |
| 130 | SIGINT: interrupted; the report says whether the stop was clean |
| 143 | SIGTERM: terminated; the report says whether the stop was clean |
| 129 | SIGHUP: hung up on, a signal it was not started ignoring |
| 131 | SIGQUIT: asked to quit, a signal it was not started ignoring |

## At a terminal

A verb's results go to standard output and its progress and notes to standard error, always.

Colour follows `--color`, whose `always` and `never` beat every variable. Under the default
`auto`, a stream is coloured only where it is a terminal and `TERM` is not `dumb`; `NO_COLOR`, set
and not empty, turns colour off, and otherwise `CLICOLOR_FORCE`, set and not `0`, turns it on, off
a terminal too. JSON is never coloured.

Marks and spinners are Unicode where the locale says UTF-8: the first of `LC_ALL`, `LC_CTYPE` and
`LANG` that is set. Elsewhere they are ASCII (`ok`, `FAIL`, `|/-\`).

Standard error animates where it is a terminal and `TERM` is not `dumb`, unless `--quiet` is
given, a run's events go to the terminal, logs are asked for at `debug` or
`trace` or through `RUST_LOG`, or a collector is named; `--color always` does not make it animate.
A verb then redraws its progress in place on a thread of its own, which nothing waits for: a
terminal that stops reading holds up neither a verb nor a signal, and a verb waits for it at its
end for a few seconds at most. What is redrawn is cleared at the end, leaving only the result, and
log lines it had no room for are counted and said then. The cursor is left visible throughout.

Where standard output is a terminal a verb prints its result in its full layout: a summary, a
table, or `Created <path>` and what to run next. Off a terminal `--output plain` keeps one line per
result, and `--output auto` prints JSON.

Where standard error is a terminal a failure is printed in its full layout, with its causes and,
where one helps, a hint; off a terminal it is one line beginning `rdlt:`.

`--quiet` drops progress, notes and event lines; results and failures always print. Text a
connector or a document supplies is shown with every control sequence escaped, on a terminal and
off it.

## JSON output

Under `--output json`, and under `--output auto` off a terminal, standard output holds JSON and
standard error holds notes.

- A verb that succeeds prints one JSON value, its result: `check`'s report, `discover`'s
  catalog, `schema`'s schema, `connectors` as `{"local", "sandboxed", "remote"}`, `init` and
  `connector new` as `{"wrote": <path>}`, `state reset` as `{"streams", "dropped", "epoch"}`,
  `certify` as `{"verdict", "passed", "reports"}`, `verdict` one of `passed`, `failed`,
  `incomplete`.
- `run` prints `{"report": <report>, "error": <failure or null>}`. With `--events -` it prints
  the events as NDJSON instead, one object a line, and then
  `{"outcome": {"report": <report>, "error": <failure or null>}}`.
- A failure is `{"error": <failure>}`, whichever verb it was. A failure of a pipeline is an
  error report: `{"kind", "origin", "stream", "code", "connector_code", "message",
  "causes", "retryable"}`, `kind` one of `config`, `schema`, `source`, `destination`,
  `transform`, `fenced`, `memory`, `internal`, `cancelled`. A failure of the command line's own
  is `{"kind", "message"}`, `kind` one of `usage`, `io`, `signal`; the last for a
  verb a signal stopped before it had a result to print.
- A usage error under an explicit `--output json` has that second form on standard output; under
  `auto` off a terminal, and in plain text, it is the usual message on standard error.
- A failure to write events or a report after the run ended is the run's `error` where the run
  has none of its own, as well as a note on standard error; the exit is 74 then.

With a collector named by `OTEL_EXPORTER_OTLP_ENDPOINT` or its per-signal variables, the process
waits about ten seconds at most at its end for what it holds to be exported, on top of its own
work; a signal does not cut that short.

A signal the process was started ignoring, as `nohup` starts it with hangups, stays ignored on
Linux. macOS has no way to see that without `unsafe`, so there it is heard as usual.
