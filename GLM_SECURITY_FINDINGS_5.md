# Security Analysis 5 — rdlt workspace (fifth deep review)

**Date:** 2026-08-15
**Scope:** same surface as rounds 1–4, reviewed at **`23dc7241`** on `047-security-hardening` (working tree clean) — the wave-5 remediation commit (~1,870 lines across 35 files: the WAL segment layout pre-pass, the stream cap + prefix-membership collision check, the expansion metering with `SharedBudget`, bounded WAL reads + the 256 MiB manifest budget, the registry merge, the sanitizer inventory completion) plus the ADR figure correction (`febad933`).
**Method:** six parallel maximally-pedantic subsystem reviews (client/protocol; WAL; engine shred/validate/budget; SDK serve + runtime; certify/testkit/reference; CLI/core/YAML/CI), each re-verifying its round-4 findings at the seat and running a fresh adversarial pass over the new code. Both new Highs and the key Mediums were re-verified by hand against the current tree and the vendored arrow-ipc/arrow-buffer sources. Non-YAML lanes could not execute tests (no C linker on the analysis host); one agent measured `serde_json` layouts directly against the workspace's compiled artifacts without linking (§8).

**Severity scale (unchanged):** High — the stated adversary (rogue connector, corrupted-WAL writer, rogue same-uid client, hostile YAML) can crash, hang, or abuse the host with trivial effort. Medium — narrower preconditions or reduced impact. Low — defense-in-depth/hygiene. Info — observations.

## 1. Executive summary

**14 of 16 actionable round-4 findings are fixed clean**, several with unusually strong verification: the WAL segment layout pre-pass (4H1) walks both dictionary and record-batch blocks with checked arithmetic against the file's own size and cannot diverge from arrow's parse (same generated verifier); the prefix-membership collision check (4H2) was proven equivalent to the old pairwise rules by counterexample hunt — no pair exists that the new check misses or over-refuses; the registry merge (4M2) holds append-only in every omit/widen/narrow sequence; the sanitizer inventory closure claim (4L1) is now **literally true against Unicode 16.0** (re-derived: zero Cf members missing). Two partials: **4H3** closed the array dimension but object-only slabs still bypass the expansion metering, and the new caps over-refuse honest shapes at two seams; **4L7** closed the under-count but the flat ×256 factor now over-refuses honest fixtures (certification false negatives). Round-4's 4I14 was not fixed and is upgraded below.

**Two new Highs, and both are old stories at newly-enumerated seats:**

1. **5H1 — the declared-length abort class (3H1/4H1) still has two naked seats.** The framing pre-pass exists only at the client's decode seat, module-private. The certifier's P5 clause decodes a *rogue connector's* Arrow frames through a bare `StreamReader::try_new` with **no pre-pass and no catch_unwind** — a ~60-byte crafted frame aborts the certifier process (uncatchable `handle_alloc_error`) or memsets 2 GiB per frame. The SDK's serve-destination seat has the panic belt but not the pre-pass — the memset and abort arms pass through it. Five rounds fixed this class seat-by-seat (client → WAL → …) instead of sharing one implementation across the three lanes.
2. **5H2 — the arena's object parser has an un-budgeted O(N²) duplicate-key scan**, pre-existing since the arena's introduction and missed by four rounds because it is not a cap violation but an algorithmic gap on the one path the new row budget doesn't meter: a flat 64 MiB JSON object (~5 M keys) costs ~1.3×10¹³ string comparisons — hours of uninterruptible CPU inside `spawn_blocking` (dropping the shred future does not stop the blocking thread), parallelizable across up to 1024 streams.

The Medium band is dominated by the **over-correction of round 4's caps** — the availability side of the ledger that pedantic review exists to read: the cell budget refuses honest 300-column × 1M-row batches (the honest ceiling at the row cap is 267 source columns); the row budget now conflates rows with array elements and refuses honest list-carrying pushes at a third of the cap; the testkit factor refuses honest >256 KiB reads. Plus one genuine gap (checkpoint cursors are uncapped in *both* directions while the new README claims "every `*_json` document payload" is capped), one WAL time-amplification residual (per-extent bounds without a sum bound → ~70 TB of read/memcpy from one crafted segment), and one reachable release-active panic (connector-declared `ident_rules.max_len` drives the naming probe-exhaustion assert).

## 3. New findings — High

### 5H1 — The declared-length abort class has two remaining naked Arrow decode seats: the certifier's P5 clause (the primary adversary's frames) and the SDK's serve-destination write path
**Where:**
- `crates/rdlt-certify/src/wire.rs:786-796` — `count_batches` = bare `StreamReader::try_new(Cursor::new(bytes), None)`, **no pre-pass, no `catch_unwind`**, called from `p5_violations` (`:742-757`) for every Arrow frame a *connector under certification* serves on a declared stream;
- `crates/rdlt-connector-sdk/src/serve/destination.rs:326-345` — `decode_arrow_ipc` has the panic belt but **no framing pre-pass**; the memset and abort arms pass through `catch_unwind`.

**Verified mechanism (vendored arrow-ipc 58.3.0, confirmed by direct read):** `MessageReader::maybe_next` executes `self.buf.resize(meta_len, 0)` — a wire-declared i32 up to 2 GiB, **committed and zeroed before `read_exact` discovers the bytes don't exist** — and `MutableBuffer::from_len_zeroed(message.bodyLength() as usize)`, whose failure path is `handle_alloc_error` → `std::process::abort()`. The negative-length `Layout` panic is contained where a belt exists; the memset is not a panic anywhere, and the abort is not containable anywhere. `MAX_FRAME_BYTES` caps the frame's *actual* bytes, not its *declared* lengths.
**Impact:** (a) the certifier faces its explicitly-declared adversary — a rogue connector — through this seat: a ~60-byte crafted `arrow_ipc` read frame **aborts the certifier process** mid-clause, or a 4-byte meta word memsets 2 GiB per frame (RSS/OOM churn until CLAUSE_TIMEOUT). Round-4's 4I14 called this seat "safe via the flatbuffers verifier" — true for *depth only*; the length vectors were never covered. (b) A rogue same-uid client aborts any served destination connector (including the reference) with one crafted Write, or churns 2 GiB memsets per frame. The client lane fixed this class in round 3 (3H1) and the WAL lane in wave 5 (4H1) — each fix was seat-local, and the pre-pass (`refuse_overdeclared_framing`) remains module-private.
**Fix:** promote the framing pre-pass into `rdlt-connector-protocol` (or the SPI crate) as one shared function; run it before `StreamReader::try_new` at both seats; belt the certify seat with `catch_unwind` as well (it currently has neither). Pin the 2 GiB meta declaration and the huge-positive-`bodyLength` cases at both seats. One implementation, three lanes — this is the third consecutive round finding a member of this class; sharing it ends the enumeration game.

### 5H2 — Un-budgeted O(N²) duplicate-key scan in the arena's object parser: hours of uninterruptible CPU from one 64 MiB push
**Where:** `crates/rdlt-engine/src/shred/arena.rs:449` — `entries.iter_mut().find(|(k, _)| *k == key)` inside `visit_map`, pre-existing since the arena's introduction (commit `83621acf`), untouched by four rounds and by wave-5's metering.
**Verified:** every object entry linearly scans all previous entries of the same object — quadratic in entries *regardless of duplicates* (the scan runs to find duplicates, but pays N²/2 even when there are none). The wave-5 row budget spends per **array element** (`visit_seq`) but **nothing per object entry** (`visit_map`), so a document that is one flat object — `"k1234567":0,` ≈ 13 bytes/entry, ~5 M entries in a 64 MiB frame — parses completely (only the document's single root row is charged) while paying ~1.3×10¹³ string comparisons. The shred runs inside `spawn_blocking`: dropping the future (cancellation) does not stop the blocking thread, so the engine's cancel token and graces are irrelevant for the duration. Across up to 1024 streams (the wave-5 cap), a rogue parallelizes this over the blocking pool. A 10 MiB push (~800 K entries, ~3.2×10¹¹ comparisons) already costs minutes.
**Impact:** typed-error-free CPU denial of service by a rogue source; also amplifies the SharedBudget starvation residual (5L7) by holding pool permits for the shred duration.
**Fix:** dedup via a per-object `HashMap<Cow<str>, usize>` index (or first-occurrence tracking) instead of `Vec::find` — one structure, O(N) — and/or spend a budget unit per object entry so the parse-time cap bounds object breadth as it now bounds array breadth. Pin an object-heavy slab at a small cap.

## 4. New findings — Medium

### 5M1 — Checkpoint cursors are uncapped in both directions while the new README claims every `*_json` document payload is capped; the inbound seat materializes untyped `Value`s from rogue frames
**Where:** `crates/rdlt-connector-client/src/source.rs:465-474` (`CheckpointCursorJson` decoded into an untyped `serde_json::Value` with **no** document cap — bounded only by the 64 MiB frame cap); `source.rs:424-427` (a stored cursor re-sent as `since_cursor_json` with no pre-send check, despite the docs claiming the client "refuses to send one"); `crates/rdlt-connector-protocol/README.md:398-402` ("Every `*_json` DOCUMENT payload… is capped at 8 MiB" — true today only for `config_json` and `since_cursor_json` at the serve gate).
**Impact:** a rogue source pushes 64 MiB checkpoint frames per read; compact-scalar JSON materializes several hundred MB of `Value` host-side — the exact many-fold expansion the document ceiling exists to prevent, on the one remaining untyped inbound seat — repeatably, and poisons persisted state so every subsequent resume against an honest serve fails at the 8 MiB gate (fail-closed availability). The README overclaim was introduced by the wave-4/wave-5 contract text.
**Fix:** refuse `bytes.len() > MAX_DOCUMENT_BYTES` typed at the `CheckpointCursorJson` decode seat (the client is the trust boundary for inbound documents; receipts/state docs are typed structs — the cursor is the one untyped seat); pre-refuse oversized cursors before re-send; scope the README sentence to the enforced fields or enforce it everywhere.

### 5M2 — WAL segment pre-pass bounds each extent but not their sum: a crafted ~100 MiB segment wedges recovery for hours in read/memcpy
**Where:** `replay.rs:123-144` (per-block `end ≤ file_len` only) interacting with arrow-ipc's eager dictionary loop and per-batch `read_block` (`reader.rs:1267-1272, 1456-1463`).
**Impact:** a `Block` is a 24-byte inline struct, so a 16 MiB footer (the cap) declares ~700 K blocks, each pointing at an extent up to the whole file (overlaps unrestricted). A non-sparse ~100 MiB crafted segment whose footer declares ~700 K blocks all referencing one small valid message forces ~700 K × 100 MiB ≈ **70 TB** of `read_exact`/memcpy — hours of single-threaded recovery work, ×2 passes, ×N for each segment the (re-checksummable, unkeyed) manifest names. Memory stays bounded; it is pure time — the round-4 "axes-bounded-products-unbounded" class one level below 4H1's fix.
**Fix:** refuse when the sum of declared extents exceeds a small multiple of `file_len` (honest is exactly one block; even `Σ ≤ 2×file_len` admits every honest segment), or cap declared block count per list (the writer emits one).

### 5M3 — The cell budget refuses honest wide×large batches with no chunking: the honest ceiling at the row cap is 267 source columns
**Where:** `shred/mod.rs:48-67` (`MAX_BATCH_CELLS = 2^28`); seats `passthrough.rs:184`, `drain.rs:259-263`.
**Impact (exact arithmetic, agent-derived and formula-verified):** at the 10⁶-row cap, `(cols+1) × 10⁶ ≤ 2^28` gives **cols ≤ 267** — a 300-column table with 1 M-row batches (3.01×10⁸ cells) and a 400-column table at 700 K rows are both refused; both are honest shapes (wide Postgres table, big read chunk) within every frame and row cap. Max-width (4096-col) tables are capped at ~65.5 K rows/push. The engine does not chunk; the typed error delegates to the source, but batch size is the source's choice. Pre-wave-5 these shapes assembled ~16 GiB (the 4H3 vulnerability) — the cap is right to refuse *that*; the collateral is the honest quadrant below it.
**Fix:** chunk assembly at the seat when `columns × rows` exceeds the budget (the row cap already provides the split axis), or make the budget configurable with the current value as default. Releasing 4H3 by refusing honest traffic is a trade the error text should at least name precisely.

### 5M4 — The row budget conflates rows with array elements: honest scalar-list pushes refuse at ~⅓ of the row cap
**Where:** `arena.rs:400-427` (every array element at every depth spends one unit) + `tape.rs:44-59` (traversal budget is rows-only); both draw `MAX_RECORD_BATCH_ROWS = 1,000,000`.
**Impact:** 300 K rows each carrying a 4-element scalar list spend 1.5 M units → typed refusal, though zero child rows materialize when the `scalar_lists` capability is on. The over-count is admitted in the comment; the effective per-push bound is now `rows + Σ|lists|`, which no connector author would guess from the row-cap name.
**Fix:** charge elements only when they will materialize rows (child-table shape vs scalar-list shape is known at traversal, not parse — spend at traversal instead), or give scalar-list cells a fractional weight; at minimum, name the effective bound in the error text.

### 5M5 — Object-only slabs bypass the expansion metering entirely: ~10× arena amplification the row budget never sees
**Where:** `arena.rs:436-458` — `visit_map` spends no budget; `Arena::sized_for` caps pre-sizing at 64 K nodes but growth is un-metered.
**Impact:** a 64 MiB frame that is one object (or objects-only nesting) builds ~5–11 M entries + nodes (~40 B each ≈ 0.4–0.9 GB arena) before the document's single `take_one` — the exact "materialize then refuse" pattern 4H3 was written to kill, closed for arrays (~22×) and open for objects (~10×). Bounded by the frame cap and the SharedBudget's in-flight bound; multiplied by concurrent streams' *derived* expansions, which the budget never sees.
**Fix:** spend a budget unit (or per-K-bytes charge) per object entry at parse — the same one-line shape as the array fix, one `visit_map` away; also the second half of 5H2's fix.

### 5M6 — Connector-declared `ident_rules.max_len` is unvalidated: small bounds make the naming probe-exhaustion assert a data-reachable, release-active host panic
**Where:** ingestion without validation at `client/src/handshake.rs:277-287` (`DestinationCapabilities` deserialized from the handshake's `capabilities_json`, no floor check); the assert at `rdlt-core/src/naming.rs:147-151` (`assert!(probe <= taken.len() + 1)` — active in release); consumption at `lowering.rs:36`, `table.rs:71`, `passthrough.rs:236`; secondary reachability via the WAL rules sidecar (`scan.rs:133`).
**Impact:** at `max_len ≤ 1` every over-long name normalizes to `"_"`, so the *second* distinct long column enters the probe loop and the assert fires deterministically; at `max_len` 2..9 the candidate space is `16^(max_len−1)` (e.g. 17 long columns exhaust `max_len=2`). A hostile or merely quirky destination declaration plus an ordinary wide source aborts the host engine process — availability, from a field SECURITY.md's trust model explicitly leaves untrusted ("wire frames, identifiers… are still treated as untrusted inputs"). The wave-5 suffix-shrink change is what made the assert *deterministically* reachable. At `hash_len=1` the bound is also probabilistic — a false-positive panic while free candidates remain.
**Fix:** refuse or clamp `max_len` below a floor (≥ 2, arguably ≥ 8) at capabilities ingestion and at the sidecar read, or return a typed refusal from `UniqueNamer::name_for` instead of asserting.

### 5M7 — Testkit's ×256 factor over-refuses honest sources: certification false negatives above 256 KiB of JSON per read
**Where:** `testkit/conformance/source.rs:77, 173-192` — the cumulative per-read charge is wire × 256 against the 64 MiB ceiling.
**Impact:** the binding constraint is now the flat pre-parse factor, not the ceiling: an honest source streaming >256 KiB of ordinary JSON in one read (true retention at typical 10–30× expansion = 6–9 MB, far under 64 MiB) fails S1 by name — a **certification false negative**, the over-refusal dual of the under-count 4L7 fixed. The measured worst case (~188× — chain-of-1-element-arrays with the 72-byte `Value` and capacity-4 first `Vec` allocation this lockfile actually has) leaves only 1.36× headroom, not the ~3.4× the comment implies (5L12).
**Fix:** meter actual retention (a counting deserializer or post-parse size walk) with the ×256 kept only as the transient bound; or raise the ceiling/factor split so honest shapes pass.

## 5. New findings — Low

- **5L1 — Validate-then-redecode TOCTOU at the WAL segment seat** (`replay.rs:37-42`): the pre-pass reads trailer+footer, then `FileReader` re-reads the same regions; a concurrent same-user attacker rewriting the footer between the two reads re-opens the abort class (microsecond window, retryable across every restart — no special sysctl needed, unlike the documented sparse/strict-overcommit residual). Fix: fstat-compare (size+mtime) around the open, or decode from a private snapshot.
- **5L2 — The 256 MiB manifest budget is honestly reachable** at the wave-5 stream cap: ~1024 streams × ~1 checkpoint/s crosses it in ~40 minutes of run time; the consequence (Damaged → clear → re-extract the uncommitted span) is crash-only and safe-direction, but silently discards the WAL's replay value exactly for big multi-stream runs, and the in-code "orders of magnitude past any honest span" claim does not hold. Raise, budget the tail only, or correct the arithmetic.
- **5L3 — Cursor contract mismatch: the wire contract allows 8 MiB persisted cursors; the WAL refuses >4 MiB lines — and the failure shape is an undocumented resume crash-loop** (honest source re-issues the same oversized cursor after every restart). State the effective bound (4 MiB line cap) in the cursor contract, or pre-refuse at the SPI boundary before it can loop.
- **5L4 — The `{:?}` refusal seats leak the two Hangul fillers raw** (`client/handshake.rs:182-186`, `source.rs:120-124`, `destination.rs:277-283`): `Debug for str` leaves Lo-category U+3164/U+FFA0 unescaped, falsifying those seats' own "the message cannot carry the bytes it refuses" invariant — the 4L2 bug class, fixed at the display seat but missed at the three refusal renderers (no terminal-control capability; invisible-glyph spoofing in diagnostics only). Render refusals through the shared escape; extend the inertness pins.
- **5L5 — Identifier seats gate content but never length or count**: a 60 MiB control-free stream name or a map of millions of state-format keys passes every gate within the frame cap (log swelling, plan noise at ~1×). A modest identifier-length ceiling and a key-count cap, in the socket path's 107-byte precedent.
- **5L6 — Serde-echo remains at the Read decode seats** (`serve/source.rs:460/479`, `serve/destination.rs:263-269`): wrong-shape errors quote the parsed token verbatim (an 8 MiB string field rides the refusal into host logs). Same-uid visibility only; kind-and-location rendering like the handshake arm closes it.
- **5L7 — SharedBudget converts a rogue stream's expensive payload into cross-stream starvation** (design-accepted, documented: "the ceiling prices the run, not the stream"): FIFO ordering and zero-byte checkpoint exemption keep it a degradation, not a hang — but the worst-case duration is unbounded *only because of 5H2*; fixing 5H2 bounds it. Optionally cap a per-stream share of the pool.
- **5L8 — Passthrough is still O(columns²) per push** (`passthrough.rs:71, 93, 161, 194` — four linear `find`s): a 4096-column table pays ~tens of ms per push; the same class 4M3 eliminated in `table.rs`/`build.rs`. Map-backed lookups, mirroring `TableBuffer`.
- **5L9 — `MAX_STREAMS_PER_SOURCE` is not configurable** (`pub(super) const`): an honest >1024-table database refuses at plan time with no operator override and no escape hatch named in the error.
- **5L10 — The cell-budget refusal fires after `registry.apply` at both seats**: a refused push has already mutated the in-memory registry and dropped its Delta. Benign today only because the error is terminal for the run; any future continue-past-error change would silently desync registry from destination. Hoist the check above `apply`.
- **5L11 — The cell-budget boundary pin models no real seat** (`shred/mod.rs:78-90`): every real table carries 1–5 system columns, so the true boundary is lower than the pin's; the doc comment's "256×1M ≈ 2⁸×2²⁰" mixes 10⁶ with 2²⁰. Pin through a seat; correct the comment.
- **5L12 — The testkit layout pin asserts the wrong invariant** (`source.rs:445-449`): it pins the dense-array bound (`≥ 3·size/2`), not the binding chain worst case (`(size + align16(4·size+8))/2`); a `Value` growth to ~100–170 B re-opens the under-count while the pin stays green. The comment's chain arithmetic (~75×, "~150 bytes/level") is also wrong — actual ~376 B/level (capacity-4 first `Vec` allocation) ≈ 188×. Pin the chain form; correct the derivation.
- **5L13 — `max_len = 0` violates the documented bound by one character** in both `normalize_ident` and `suffixed` (both return `"_"`), uncovered by tests; refuse it typed or amend the claim.
- **5L14 — Stream-name display seats use the control-only sanitizer** (`ui/pretty.rs:91,122`, `run.rs:173-174`): joiners (admitted at identifier gates by design) render invisibly in the CLI, below every other seat's "rendered text cannot hide an inventory character" bar. Escape stream names through the shared full predicate.

## 6. New findings — Info

- **6.1 — No honest-boundary pin for the 16 MiB footer cap** (`replay.rs:19, 107`): today's honest footer is ~0.6 MiB (~27× headroom); growth of the column cap or arrow's encoding would flip honest segments to refusal with nothing failing first.
- **6.2 — Device-node fixtures unpinnable without CAP_MKNOD** (4I6 residue): the same `is_file()` branch is exercised by the FIFO/directory pins.
