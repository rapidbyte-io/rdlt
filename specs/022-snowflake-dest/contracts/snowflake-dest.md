# Contract: Snowflake Destination Rules (SD1–SD8)

| # | Rule |
|---|---|
| SD1 | One library, one boundary: the destination speaks Snowflake ONLY through `snowflake-connector-rs`, wrapped at exactly one module boundary (the duckdb-rs precedent) — session lifecycle, statement execution, and error translation (`snowflake_code()`/`ErrorKind` → SPI taxonomy) live behind it; no library type crosses the crate's public surface. The internal-stage PUT gap is source-verified and deferred on a named upstream trigger with the issue filed; the hand-rolled session client is the designed, escalated fallback — never an improvised sidecar beside the crate. |
| SD2 | The full unattended auth vocabulary, every secret guarded: key-pair JWT (encrypted and plain PKCS#8, passphrase source), password (with the documented MFA/user-TYPE caveats and optional passcode), OAuth access token, and PAT — each Secret-wrapped from parse and grep-proofed (debug, serialize, error paths), each with a LIVE leg gated on its own credential presence, skip-not-fail. Interactive external-browser SSO is typed-unsupported. Auth, permission, and network failures are distinguishable BY SHAPE. No account identifier, user name, or secret material may exist in any committed file at any commit of this feature — mechanically verified at close. |
| SD3 | The atomic unit is pure DML: publish, receipt insert, and state update commit in ONE explicit transaction; ALL DDL (table create, add-column, stage create) executes strictly before any unit opens, and the unit-scoped executor REFUSES DDL statement kinds — the invariant is code, not convention, because DDL auto-commit was proven live to silently commit an open transaction. Replay of a receipted (load, seq) publishes nothing and returns the prior receipt. |
| SD4 | Merge without enforced constraints: key identity and last-wins dedup are delivered by the MERGE construction itself (`QUALIFY ROW_NUMBER() … DESC = 1` in the USING subquery — proven live); the full shared options vocabulary validates identically to the other SQL destinations; duplicate-merge-key situations classify by structured code 100090 into the shared diagnosis. All emitted SQL is golden-pinned byte-for-byte, and the postgres/duckdb golden pins are byte-identical before and after this feature, including through both sqlcore extractions. |
| SD5 | Identifier policy is total: every rdlt-owned identifier is emitted quoted-uppercase (`"EVENTS"`), catalog reads compare the uppercased form exactly, and hostile identifiers (reserved words, specials, mixed case) round-trip by pin. The `_rdlt_` persisted-name constants remain the single source, uppercased at the emission boundary only. |
| SD6 | Ingestion is verified on every shipped path: batched INSERT (universal default; batch size measured, not guessed) and external-stage `COPY INTO` (user bucket; parquet parts written by the workspace's own machinery; per-COPY loaded-rowcounts verified against staged counts — a mismatch fails the unit typed). Staged artifacts are pipeline-owned (part-name shape), crash-reclaimable, never another pipeline's to touch. Internal-stage PUT is a recorded deferral (upstream trigger), surfaced in the dlt-parity matrix — the connector never claims a bulk path it does not have. |
| SD7 | Crash discipline: `sf.stage.write` / `sf.unit.publish` / `sf.receipt.visible` swept ×3 actions against the LIVE qual account (credential-gated, skip-not-fail), converging to exactly-once totals with zero duplicate publishes. Statement economy is contractual: a steady-state load over an unchanged schema issues ZERO schema-mutation statements (describe-once ensure), instrumented by mock-transport counts and verified once live. |
| SD8 | Verification per house standard: destination-conformance certification; differential oracle vs the postgres destination (canonical-row equality incl. SCD2 history openness) for the full strategy matrix on the live leg; dlt-parity matrix with named deviations; coverage ≥80% baseline-first; close-out matrix zero uncited dispositions with both fired sqlcore extraction triggers terminally dispositioned; recorded UNBARRED ingestion session (no SaaS bar, existing bars untouched); purely additive semver at every increment merge. |
